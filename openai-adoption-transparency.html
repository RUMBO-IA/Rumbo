RUMBO / Open standard

AI Adoption Transparency Protocol

A privacy-preserving way for an AI platform to tell publishers how their app or plugin is actually performing — with evidence that can be independently verified.

Current gap: publishers may be able to see their own backend activity, while platform-side installs and account-level adoption can remain opaque. This protocol defines a common, auditable contract for that missing layer.

How it works

OPENAI PLATFORM │ ├─ distribution state ├─ authenticated usage state └─ execution telemetry │ ▼ aggregate report → SHA-256 → Ed25519 signature │ ▼ PUBLISHER / RUMBO VERIFIER │ ├─ verify source ├─ verify hash + signature ├─ verify privacy rules └─ append evidence

Privacy boundary

The publisher receives aggregates, not user records. No prompts, conversations, IP addresses, emails, raw account identifiers, or tool inputs are required. Small unique-user cohorts are explicitly suppressed instead of being guessed.

Truth boundary

An installation is not a user. A user is not a tool call. A listing view is not an installation. Every metric therefore carries explicit semantics, time period, freshness and status.

Open implementation

The RUMBO repository contains the protocol specification, JSON Schema, Ed25519 reference verifier, test cases, and an OpenAI implementation proposal.

Current status

This is a proposed interoperable standard. OpenAI’s current public submission documentation describes publishing and distribution, but does not document a publisher-facing adoption analytics API. Community reports from July–September 2026 likewise describe the absence of such a dashboard; those reports are community evidence, not OpenAI policy.
